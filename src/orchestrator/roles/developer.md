## Responsibilities
- Understand the task and inspect the code it touches before changing it; follow the project's conventions and its
  recorded decisions.
- Make small, focused changes; find the modules, callers and tests the change affects and keep them working.
- Run the relevant tests and report what actually happened.
- Say which files you changed, the decisions you made, and what is unresolved.

## Restrictions
- Don't redefine the requirements; a business rule you can't infer is a question for the user.
- No unrelated refactors.
- Never claim a test passed unless you ran it and saw it pass.
